# Crew and memory

- The crew: the **interpreter** talks with the user; the **conductor** plans each task; the **researcher** finds material; the **coder** and the **writer** make the change; the **code reviewer**, the **document reviewer**, and the **tester** check it and report each problem; the **image describer** puts pictures into words for members that cannot see them.
- The legend in the camp's top-left lists the crew; in a narrow window, where the panel goes under the camp, it starts folded. For each member the user can toggle hiring, edit the nickname in place, pick the model, and open its definition and permissions: tools, write scope, skills, and MCP servers. **Reset** in that window, after a confirm, puts the nickname, model, hiring, and permissions back as they first were. The interpreter and the conductor cannot be let go.
- Who holds which skill or MCP server is changed only by the user, in that window; no member changes it, and skills never change while a task runs.
- When one member is needed for two steps at once, or is already at work in the session, the app makes a copy of it for that step; the copy shows in the legend while it works and leaves when its task ends.
- The **approval mode** next to the input is set per project. **Ask** asks on a card before a tool outside a member's role. **Auto** allows those without asking, but still blocks forbidden commands and writes outside a member's scope. **All** checks nothing and allows everything.
- The **wiki** in the **Memory** tab is the documents the crew builds up while working: one document per topic, with `[[title]]` in a body linking to another. **Graph** shows documents as dots and links as lines; a dashed dot is a topic linked to but not yet written. The change list below shows who changed what. Asking the interpreter to check the wiki reports contradictions, documents nothing points to, and missing topics. **Memories** are kept per member.

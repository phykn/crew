# AI Crew 전체 리빌드

## Core

사용자는 한 비서와 대화하고, 수평적인 크루가 업무를 계획·실행·검증해 같은 대화로 결과를 돌려주는 로컬 데스크톱 앱을 전체 범위에서 다시 만든다.

## Requirements

- R1: 기준 앱과 신규 앱을 각각 재현할 수 있다. 기존 동작, 문제의 코드 위치, 새로 작성할 파일과 검증을 연결하고, 실행 코드와 보조 산출물까지 기준선의 모든 경로를 작업에 배정한다.
- R2: 기존 SQLite와 첨부 데이터를 열어 프로젝트·세션·초안·대화·업무·역할·권한·기억·위키·워크플로우 버전·산출물·알림을 이어서 사용할 수 있다. 이전에 실패해도 원본 사본이 남고 다음 실행에서 재시도할 수 있다.
- R3: 로컬 폴더 선택, 최근 프로젝트 전환, 재연결, 세션 제목·최근 활동과 초안 복원, `/clear`, 프로젝트와 세션 삭제를 제공한다. 삭제는 영향 범위를 확인하고 진행을 정리한 뒤 실행한다. 프로젝트 원본 파일과 위키의 삭제된 세션 출처 표시는 남는다.
- R4: 한 채팅에 사용자와 비서만 발언한다. 답변 중 전송, 대기열과 개별 취소, 중단과 재개, 이미지 하나만 전송, 한글 조합, 키보드 조작과 초안 격리가 동작한다. 미실행·취소된 요청의 텍스트와 이미지는 모델 입력에서 빠진다. 늦게 도착한 응답은 현재 탭·세션·초안을 덮어쓰지 않는다.
- R5: 사용자가 역할별 Codex·로컬 LLM을 선택한다. 이전 모델 스레드가 살아 있으면 이어가고, 사라지면 저장된 맥락으로 복구한다. Codex의 새 턴·재개·복구 모두 현재 첨부의 비전 설명을 받는다. 모델 한도·연결 오류·중단이 구분되고 사용량·시간과 확인 가능한 비용이 남는다.
- R6: 짧은 요청에는 비서가 답하고, 복합 업무는 계획과 계획 검토, 개발, 리뷰·코딩 스타일·테스트, 비서 확인으로 흐른다. 동료 요청과 인계, 불명확한 후속 지시, 단계별 체크포인트, 실패 시 3회 재시도, 재검증, 복구 및 최종 보고가 업무와 실행 ID로 연결된다.
- R7: 현재 역할·스킬·MCP 권한과 승인 모드가 UI·도구 실행·재개에서 일치한다. 수동·비서 판단·항상 승인을 적용하며, 범위가 바뀌면 다시 판단한다. 겹치는 수정, 오래된 승인, 이전 검증과 중단 경합에서 최신 버전과 사용자 변경을 보존한다. Git 업무 격리, 검증과 원본 반영, 산출물 조회와 정리를 구분한다.
- R8: 인사팀이 능력이 부족할 때 에이전트를 고용하고 비서가 채택·해고를 판단한다. 정규 팀원은 `고용`·`미고용` 사이에서 되돌릴 수 있고 알바는 업무를 남기고 퇴장한다. 범례에서 역할·별명·모델·활성 업무·스킬 상태·권한과 지침을 확인한다.
- R9: React Flow 워크플로우는 세로로 그려지고 노드·연결을 직접 편집한다. 프로젝트별 초안과 버전이 남는다. 기본 적용은 새 업무부터이며, 기존 업무에 적용할 때 바뀐 단계와 근거만 다시 확인한다. 잘못된 저장은 편집 중인 그래프를 보존한다.
- R10: 개인 메모리와 프로젝트 공유 위키는 읽기·쓰기·삭제 범위가 구분된다. 위키 목록·노드·타임라인이 같은 문서와 출처를 보여준다. 문서와 이력이 같이 저장되고, 충돌 시 기존 내용과 초안이 유지되며, 연결된 규칙은 사용자 선택에 따라 처리된다.
- R11: 화면과 도우미, 실제로 연결한 앱 MCP가 한 동작 등록부와 실행 경로를 사용한다. 화면 액션 ID와 MCP 검색 결과를 대조할 수 있고 동일 조건에서는 승인·저장·로그·이벤트 결과가 일치한다. 현재 권한·소유권·버전·중복 요청을 검증하고, 화면 조작의 적용 상태를 원래 대화에 알린다.
- R12: 채팅·로그·메모리·워크플로우가 공통 크기와 토큰을 쓰고, 세션은 인라인 목록으로 선택한다. 입력줄에서 프로젝트와 승인 모드를 바꾸며 진행 카드는 채팅 상단, 답변이 필요한 질문은 입력창 가까이에 둔다. 캠프·카드·로그가 같은 상태를 읽고, 픽셀 캠프에서 자율 이동, 고용·퇴장, 인계, 작업 표시와 별명·대사가 보인다.
- R13: 기준선과 리빌드 이후의 타입 검사, 자동 테스트, macOS 패키지와 패키지 기반 핵심 시나리오를 재현한다. 이전 DB·모형 Codex·로컬 모델 및 앱 MCP 통합 검증을 함께 통과하고, 실행 문서와 목업 설명은 실제 앱 동작과 일치한다.

## Design

- `src/shared/`, `src/preload.ts`, `src/backend/main.ts`는 공유 입력·이벤트 계약, 제한된 렌더러 브리지, 앱 수명 주기를 담당한다. Electron 진입점은 도메인 서비스를 조립하고 시작·종료한다. (R1, R3, R4, R7, R11, R13)
- `src/backend/store/`는 한 SQLite 연결과 트랜잭션을 업무별 저장 모듈로 연결한다. 원본 스키마와 마이그레이션 기록을 호환 기준으로 삼는다. 화면·캠프·로그용 결과는 한 번 읽은 상태를 공유한다. (R2, R3, R4, R6, R7, R8, R9, R10, R12)
- `src/backend/server/chat/`, `src/backend/server/codex/`, `src/backend/server/diagnostics/`는 채팅 수명 주기, 모델 응답과 재개, 비전·진단·사용량을 담당한다. 런타임과 진단은 같은 모델 및 실행 파일 선택 규칙을 사용한다. (R4, R5, R13)
- `src/backend/workflow/`, `src/backend/server/mcp/`는 업무 단계, 인계·체크포인트, 현재 권한에 따른 도구 접근과 검증 및 원본 반영을 맡는다. (R6, R7, R8, R9)
- `src/backend/server/app/`은 역할이 사용 가능한 앱 동작과 읽기 경로를 등록한다. IPC, 도우미 호출과 MCP 연결은 같은 등록부를 통한다. (R3, R7, R9, R10, R11)
- `src/frontend/`, `index.html`은 화면 배치와 탐색, 상태 표현과 캠프 렌더링을 담당한다. 세션 전환과 비동기 결과는 대상 ID와 버전으로 처리한다. (R3, R4, R8, R9, R10, R11, R12)
- `tests/`, `scripts/`, `demo/`, `agents/`, `docs/`, 루트 구성·문서는 실행 증거, 목업, 사용자 지침과 빌드 경로를 재현한다. (R1, R12, R13)

## Decisions

- 기준은 로컬 `refs/ai-crew/rebuild-baseline`의 커밋 `c4caafa68f664f063d00f44f156f24ccb54c3867`이다. 부모 `e914ca849456573c66022b2fd511b59326799d7a` 위의 채팅·진단 수정 12개 파일을 포함하며 `git diff --exit-code refs/ai-crew/rebuild-baseline`로 등록 당시 작업 트리와 비교했다. 작업 중인 `main`과 기존 스태시는 그대로 뒀다.
- 근거는 기존 `docs/plan/PLAN.md`와 `agents/interaction.md`, `agents/execution.md`, `agents/app-mcp.md`, `agents/APP_MANUAL.md` 및 기준선의 실행이다. 과거 계획은 변경 이력으로 두고, 리빌드 진행은 이 파일에서 관리한다. 구현과 명세가 엇갈릴 때 기존 제품 결정을 우선하고 차이를 검증 항목으로 옮긴다.
- 프로젝트·세션 삭제와 재연결은 화면 명세에 있지만 `src/shared/actions.ts` 및 `src/backend/server/app/actions.ts`의 진입점은 선택과 열기만 등록한다. 세션 목록은 `src/frontend/ui/panels/toolbar.tsx`에서 제목만 그린다. 삭제와 이동 시의 원본 보호를 실제 흐름으로 검증한다.
- 앱 MCP 생성 함수 `src/backend/server/app/mcp.ts`의 호출자는 단위 테스트에만 있다. 로컬 모델에 들어가는 `src/backend/server/app/tools.ts`의 도우미 도구와 실제 앱 MCP 연결은 동일한 등록부에서 제공하고, 패키징한 앱에 클라이언트를 연결해 확인한다.
- `src/backend/server/app/actions.ts`의 중복 처리는 요청 ID와 전체 인자를 한 키로 삼고 동작 완료 뒤에만 저장한다. 동일 ID로 인자를 바꾼 요청과 완료 전의 동시 재전송을 구분하는 검증을 앱 MCP 테스트에 넣는다.
- 메인 진입점이 응답·대기열·도구·IPC·창 수명 주기를 함께 처리한다. `src/backend/store/store.ts`의 저장소 상속 사슬이 기능 경계를 가로지르고 `src/backend/store/snapshot.ts`는 캠프용 배정·업무·스킬 리소스를 중복 조회한다. 수명 주기와 저장 조회 경계를 나누고 화면과 캠프에 동일한 읽기 결과를 전달한다.
- `src/frontend/renderer.tsx`의 새 스냅샷은 호출의 대상과 최신 선택을 대조하지 않고 적용한다. 응답 순서를 뒤집는 테스트로 세션과 초안 격리를 검증한다. `src/frontend/workspace.css`는 5,151줄이며 같은 컴포넌트의 뒤쪽 재정의에 의존한다. 토큰과 뷰 단위로 재구성하고 채팅·워크플로우 간 같은 패널 폭을 비교한다.
- 사용자가 정한 픽셀 캠프 원화·스프라이트와 라이선스가 있는 글꼴은 새 렌더러의 원본 리소스로 사용한다. 프로토콜 타입, 잠금 파일, 데모 번들은 해당 생산 도구로 생성한다. 연구·콘셉트 원본을 다시 정리할 때 출처와 사용자가 선택한 시안을 보존한다.
- 새 환경에 대한 기본 검증은 모델 응답과 오류를 통제할 수 있는 모형 서버를 쓴다. 실제 Codex와 연결된 로컬 모델의 스모크 테스트는 어댑터 호환성 검증에 사용한다.
- 기준선에서 타입 검사, Vitest 49개 파일의 194개 테스트, macOS arm64 패키징이 통과했다. 실제 Qwen3.6을 사용한 패키지 검증은 폴더 선택, 비서 답변, 초안 복원, `project_info`와 로그 진입까지 진행했다. `scripts/desktop-smoke.mjs:70`에서 한 줄로 합쳐진 옛 로그 문구를 기다리지만 실제 화면은 역할·상태와 본문을 따로 렌더링한다. 패키지 검증에서는 표시 구조에 맞춰 로그 본문과 역할을 식별한다.
- 임시 검증본에서 로그 위치만 바꾸면 사용량 확인과 응답 중단까지 통과한다. 다음 자연어 `/clear` 질문의 응답이 진행 중인 동안 `scripts/desktop-smoke.mjs:85`의 기본 5초 UI 대기가 만료됐다. 명령어와 자연어 구분은 응답을 제어하는 모형으로 검증하고, 실제 모델의 확인은 연결·응답·중단 상태를 관찰해 판정한다.

# Kit

1. Read the kit and who holds what with `read_kit`. If something there does the job, the change is giving it to one more member.
2. Decide who gets it: only the members whose own work needs it, never everyone by default. A temp may get skills but no MCP server.
3. Propose the change with `assign`: the member, its full new list of skills or MCP servers, and the reason in Korean. The user approves or cancels it on a card.
4. When nothing in the kit fits, name the smallest tool that would: a skill, or an official or widely used MCP server pinned to a version with its source. Never pick a package you cannot name a source for. Bringing a new tool into the kit is the user's step.

# Brief

Use it whenever you start a task with `start_task` or reopen one. The request is all the crew knows about what the user wants.

- Goal: one line saying what the user wants, in their words where you can.
- Scope: exactly what the user asked, neither smaller nor larger, with what stays out and any files, pages, or limits they named. Do not narrow it to files yourself; making it smaller or larger, such as a fix in place of a rewrite, needs the user's yes first.
- Kind, for a code change: a bug fix, new behavior, a removal, a refactor, or a speedup.
- Done when: what the user will see or be able to do when it is finished, written so someone can check it; for a code change, include that its tests pass.
- Settled: what you agreed with the user in the chat, which the crew cannot see otherwise.
- Assumed: what you decided yourself without asking.
- Leave out how to do it; the conductor works that out.
